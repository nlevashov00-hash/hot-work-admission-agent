# Реализация этапа

1. Получи у пользователя идентификатор этапа, если он не указан. Прочитай `PLANS.md`, описание этапа, зависимости и критерии приёмки. Если план отсутствует, этап не найден или его согласование не подтверждено, остановись и сообщи об этом.
2. Проверь состояние репозитория и наличие незакоммиченных изменений. Установи по доступным свидетельствам, выполнены ли и согласованы ли предыдущие этапы и зависимости. При неподтверждённых зависимостях остановись и запроси уточнение; не считай наличие файлов доказательством согласования.
3. Изучи относящиеся к этапу `AGENTS.md`, `REQUIREMENTS.md`, `ARCHITECTURE.md`, `BUSINESS_RULES.md` и существующий код. Сохраняй пользовательские изменения.
4. Реализуй только согласованный этап, напиши необходимые тесты, запусти соответствующие проверки и исправь обнаруженные ошибки в его рамках. Не заявляй о проверках, которые не запускались.
5. Проверь изменения относительно архитектуры, безопасности, требований и критериев приёмки. Сообщи изменённые файлы, реализованные функции, выполненные команды и их результаты, ограничения и статус каждого критерия приёмки.
6. Остановись и дождись согласования пользователя. Не переходи самостоятельно к следующему этапу. Контрольную точку Git создавай только с разрешения пользователя.

Не изменяй утверждённую архитектуру, исходное ТЗ и оригинальные эталоны без согласования; не подгоняй результаты eval. Не выполняй git commit без разрешения пользователя.

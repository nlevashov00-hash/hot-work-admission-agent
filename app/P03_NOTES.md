# P03: настройки и ограничения

Клиент использует `LLM_BASE_URL` (базовый URL API, например с `/v1`), `LLM_API_KEY` и `LLM_MODEL`; ключ не записывается в настройки проекта. Используется endpoint `chat/completions` и стандартная библиотека Python, дополнительные зависимости не нужны. Перенаправления запрещены. Таймаут сетевой операции — 30 секунд, максимум две попытки, текст до 12 000 символов, HTTP-ответ до 1 000 000 байт. Пустой или слишком длинный текст не отправляется модели.

Системный промпт `p03-v1` отделён от текста заявки ролью сообщения. Проверяются формат, согласованность фактов и наличие дословных оснований в заявке. Это не гарантирует правильность извлечения или защиту от всех инъекций: модель может ошибиться, в том числе неверно интерпретировать существующий фрагмент. При сбое факты отсутствуют; вызывающая сторона должна использовать `failure_result` и не допускать заявку. Сквозная обработка и журналирование относятся к P04. Сырые ответы и ограниченная информация о токенах и попытках доступны в результате извлечения; исключения сервера не сохраняются, чтобы не раскрывать секреты.

По сообщению пользователя, реальный smoke test клиента P03 прошёл для обеих заявок с первой попытки без ошибок; извлечённые факты соответствовали ожидаемым. Эти результаты предоставлены пользователем, а не получены самостоятельно в рамках текущей задачи. Нерешённый вопрос P02 о независимости явно названного наблюдающего сохраняется: промпт не предполагает независимость без явных сведений.

Диагностический smoke test запускается из корня проекта командой `python -m app.smoke_test`. Он читает три переменные из `.env`, выполняет заявки 1 и 8 из ТЗ и возвращает ненулевой код при ошибке. Вывод содержит ответы модели и факты: обращайтесь с ним как с потенциально чувствительными данными. Номер попытки, безопасная категория, HTTP-статус, тип сетевой ошибки и длительность сохраняются без текста исключений и заголовков. По сообщению пользователя прямой запрос к Groq из его PowerShell успешно выполнен; именно этот smoke test клиента P03 в окружении Codex не запускался из-за сетевых ограничений.

По диагностике пользователя вне Codex минимальный запрос urllib со стандартным User-Agent получил HTTP 403 от Cloudflare, а тот же запрос с явным User-Agent — HTTP 200. Клиент теперь отправляет `HotWorkAdmissionAgent/1.0`; при HTTP 401 и 403 повтор не выполняется, остальные ошибки ограничены двумя попытками. После этого исправления пользователь сообщил об успешном smoke test полного клиента.

Результаты пользовательского запуска: Groq, `openai/gpt-oss-120b`, промпт `p03-v1`. Заявка №1: 507 входных, 1185 выходных, 1692 суммарных токена, latency 3.109 с. Заявка №8: 489 входных, 1064 выходных, 1553 суммарных токена, latency 3.562 с. Эти метрики не измерялись самостоятельно в текущей задаче. Два успешных запроса не доказывают общую устойчивость к prompt injection и галлюцинациям; совпадение evidence с подстрокой заявки не гарантирует смысловую достоверность.

Для удалённых endpoint требуется HTTPS; HTTP разрешён только для `localhost`, `127.0.0.1` и `::1`. Все HTTP-редиректы запрещены. Smoke test проверяет также ожидаемые состояния и значения выбранных фактов; это не полноценный eval.

# Hot Work Admission Agent

Прототип проверяет заявки на огневые работы по вымышленному регламенту и возвращает **ДОПУСТИТЬ**, **ОТКАЗАТЬ** или **ЭСКАЛИРОВАТЬ**. При технической ошибке или недостатке данных заявка не допускается: без подтверждённого нарушения она передаётся человеку. Подтверждённое нарушение имеет приоритет отказа, даже если другие сведения неизвестны.

## Как устроен агент

Одна LLM извлекает из текста структурированные факты и фрагменты-основания. Python проверяет формат и согласованность фактов, затем детерминированно оценивает П1–П7; модель не принимает итоговое решение. Pipeline обрабатывает пакет по порядку, сохраняет идентификаторы и формирует `id`, `decision`, `rules`, `explanation`, `missing`. Для каждой заявки создаётся отдельная запись аудита: вход, время, модель, версия промпта, попытки и ответы или ошибки, проверенные факты, статусы правил и итог. При ошибке записи журнала процесс завершается с ненулевым кодом.

## Быстрый запуск через Docker

Нужны Docker с работающим Linux daemon, доступ к OpenAI-совместимому API и ключ. Для воспроизведения указанного eval использовались Groq и `openai/gpt-oss-120b`. Другую совместимую модель можно задать через переменные окружения. Сборка загружает официальный `python:3.11-slim` и устанавливает системный Git для одного из автономных тестов; сторонних Python-зависимостей нет.

Создайте вне репозитория файл `llm.env` в формате Docker `--env-file` (без кавычек вокруг значений) и подставьте свои значения:

```text
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_API_KEY=<ваш_ключ>
LLM_MODEL=openai/gpt-oss-120b
```

Не добавляйте этот файл в репозиторий. В отдельном каталоге данных создайте `input.json` в UTF-8, например:

```json
[
  {"id": 1, "text": "Наряд НД-114. Инструктаж по ПБ 03.09.2026. Работа в боксе. Огнетушитель и наблюдающий на месте."}
]
```

Запускайте команды из корня проекта. **Windows PowerShell** (подставьте существующий абсолютный путь к файлу переменных):

```powershell
docker build -t hot-work-p07 .
$dataDir = (Resolve-Path .\data).Path
docker run --rm --mount "type=bind,source=$dataDir,target=/data" --env-file <путь-к-llm.env> hot-work-p07
```

Каталог `data` и файл `input.json` создаются заранее. Вместо `<путь-к-llm.env>` укажите реальный путь без угловых скобок, при необходимости в кавычках. На Linux/macOS аналогичный синтаксис для существующих `./data` и `./llm.env`:

```sh
docker build -t hot-work-p07 .
docker run --rm --mount "type=bind,source=$(pwd)/data,target=/data" --env-file ./llm.env hot-work-p07
```

В контейнере приложение читает `/data/input.json`, пишет `/data/output.json` и создаёт записи в `/data/journal/`. Пакет — непустой JSON-массив объектов с уникальными `id` и строковым `text`. При повреждённом входе или ошибке журнала проверяйте ненулевой код процесса; оставшийся от прежнего запуска `output.json` не является результатом неуспешного запуска. Журнал содержит тексты заявок и ответы модели, поэтому его следует хранить с ограниченным доступом.

Для локального запуска без Docker нужны Python 3.11 и переменные `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` в окружении процесса. Команда `python -m app.pipeline --data-dir <каталог>` использует тот же файловый контракт; приложение само не загружает `.env`.

## Автономные тесты

После сборки выполните на любой из указанных платформ:

```sh
docker run --rm hot-work-p07 sh /app/run_tests.sh
```

Тесты не требуют ключа или реальной модели; LLM-клиент подменяется. Скрипт возвращает ненулевой код при ошибке. Также локально: `python -m unittest discover -s tests -v`. В проверке контейнера прошли 45 тестов. Сборка, команда тестирования и стандартный Docker-запуск с одной заявкой проверены в Windows/Docker Desktop; приведённая команда Linux/macOS использует тот же контракт, но на этих ОС отдельно не проверялась.

## Результаты eval

Финальный прогон 21.11.2026: Groq `openai/gpt-oss-120b`, промпт `p06-v2`, temperature 0. Всего 24 заявки, из них 21 с эталоном:

| Группа | Accuracy |
|---|---:|
| Официальные эталоны | 6/8 — 75% |
| Собственные случаи | 13/13 — 100% |
| Все размеченные | 19/21 — 90,48% |

Финальный прогон 24 заявок занял приблизительно 724,66 с, или 30,19 с на заявку при намеренном интервале 30 с между началами попыток; это не измерение максимальной пропускной способности. Ориентировочная стоимость — $0,028459 / 24 ≈ $0,00119 на заявку: оценка по 19 020 входным и 42 676 выходным токенам, включая повтор, при опубликованных тарифах Groq $0,15 и $0,60 за миллион токенов. Фактическая стоимость на заявку достоверно не измерена: неизвестны скидки за кэш, тариф аккаунта, налоги и возможное неучтённое использование. Условия и источник цены приведены в [eval_report.md](eval_report.md).

False Admission — 0, итоговых технических сбоев — 0. Заявки 9–11 не имеют официальных эталонов и не входят в accuracy. Собственный набор использовался при улучшении извлечения и не является независимой оценкой обобщения. Матрицы ошибок, фактические результаты и анализ: [eval_report.md](eval_report.md); 11 результатов: [results.json](results.json).

## Ограничения и безопасность

- Модель может пропустить, исказить или неверно интерпретировать факты. Например, в финальном прогоне заявки №11 она не извлекла указанный номер наряда.
- Для №1 и №4 результат отличается от официального эталона из-за согласованной трактовки неизвестных сведений: отсутствие упоминания близости склада, высоты или письменного согласования не доказывает их безопасное либо нарушающее состояние. Подробности — в [BUSINESS_RULES.md](BUSINESS_RULES.md) и отчёте.
- Текст заявки передаётся как недоверенное пользовательское сообщение отдельно от системных инструкций; промпт запрещает выполнять вложенные команды. Ответ валидируется локально, включая дословность оснований и согласованность фактов. Это не гарантирует защиту от prompt injection или смысловую достоверность извлечения.
- Таймаут сетевой операции — 30 секунд, максимум две попытки. При HTTP 429 учитывается `Retry-After`, иначе применяется ограниченный backoff с jitter; максимальное суммарное ожидание повтора — 30 секунд. HTTP 401/403 не повторяются. Технический сбой ведёт к эскалации; ошибка журнала прекращает запуск.
- Это прототип по вымышленному регламенту, а не полноценная промышленная система безопасности. Два предыдущих прогона и финальный eval не доказывают устойчивость на новых заявках.

## 500 заявок за смену

Первым шагом измерить на репрезентативных заявках задержку, токены, частоту ошибок и фактические лимиты выбранного аккаунта, затем подобрать ограничение частоты и обработку 429. В финальном eval 24 заявки заняли приблизительно 724 секунды при намеренном интервале 30 секунд между началами попыток; это не измерение максимальной пропускной способности. В первом прогоне без такого интервала 17 заявок завершились технической эскалацией после HTTP 429. Подробные условия, стоимость и ограничения расчёта — в [eval_report.md](eval_report.md). Только после измерений имеет смысл решать, нужна ли ограниченная параллельность или очередь.
